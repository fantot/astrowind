看到“270 亿激活参数”，不少人的第一反应是：这是不是一台工作站就能跑的 27B 模型？

不是。

阶跃星辰在 2026 年 10 月 15 日开放的 **Step 5 Preview**，是一款总参数约 6000 亿、每个 token 激活约 270 亿参数的稀疏混合专家模型。它确实不用在每次计算中激活全部参数，但推理时仍要保存和调度完整模型权重。官方 FP8 部署示例从 4 张 B300 或 8 张 H200 起步，BF16 版本则从 8 张 B300 或两台共 16 张 H200 起步。

这显然不是普通电脑上的“本地小模型”。

Step 5 Preview 真正值得关注的，不是个人能否把它塞进显卡，而是开放权重后，企业和云服务商可以在自己的环境里部署一款面向长周期智能体的软件工程模型，并通过 OpenAI 兼容接口接入现有工具链。

如果你只是想试用，它的托管 API 比下载数百 GB 权重现实得多；如果你准备私有化部署，硬件、长上下文成本和许可证条款都要先算清楚。

> 本文依据 StepFun 在 Hugging Face 发布的模型卡、部署说明和 StepFun Model License 1.0 整理。模型仍标注 Preview，代码、推理框架支持和评测结果可能继续更新，实际使用以仓库最新版本为准。

## 6000 亿总参数、270 亿激活参数，到底是什么意思

Step 5 Preview 采用稀疏 MoE，也就是混合专家架构。

可以把它想成一家有很多专业部门的咨询公司。总参数代表公司拥有的全部知识和能力；处理一个问题时，路由器只选择少数相关专家参与，所以每个 token 实际参与计算的参数约为 270 亿。

这样做能降低单次计算量，但有两个常见误区。

第一，**激活参数少不等于权重文件小**。没有参与当前 token 计算的专家，下一次仍可能被调用，因此完整权重通常还要保存在 GPU 显存或可高速访问的存储中。

第二，**MoE 不等于免费加速**。不同 GPU 之间需要传输 token、调用不同专家并合并结果。如果互联带宽、专家并行和调度做不好，硬件可能把大量时间花在等待数据上。

所以选部署方案时，不能只拿“27B active”与普通 27B 稠密模型横向比较。前者的计算量可能接近较小模型，存储和通信复杂度却不是一个级别。

## 百万 token 上下文，不是一个可以随便拉满的输入框

官方模型卡写明最高支持 100 万 token 上下文，而且部署说明进一步强调：这个上限由输入和输出共同占用。

如果输入已经用了 90 万 token，理论可用输出空间就不再是完整的 100 万。更重要的是，上下文越长，KV Cache 占用越高，并发能力也会下降。

官方在 BF16 部署说明里特意提醒，即使按推荐卡数装下模型权重，也不保证有足够显存处理完整的 100 万 token 请求，因为 KV Cache 和运行时缓冲区还会继续消耗显存。

这意味着“支持百万上下文”和“可以便宜、稳定地并发处理百万上下文”完全不是一回事。

多数业务并不需要把整个代码仓库或几年财报一次性扔进模型。更实用的做法是：

1. 先用搜索或向量检索找到相关文件；
2. 只把当前任务需要的模块、日志和文档放入上下文；
3. 给模型保留足够输出和工具调用空间；
4. 长任务按阶段保存结果，避免每轮重复携带全部历史；
5. 用真实请求统计显存、首 token 延迟和吞吐，而不是只看理论上限。

百万上下文最有价值的场景，通常不是“什么都塞进去”，而是任务确实需要跨越大量材料：大型代码仓库重构、多年合同审查、连续会议与邮件整理，或者跨季度财务研究。

## 它到底支持哪些输入？模型卡里有一个需要注意的差异

StepFun 在模型卡介绍中写到，Step 5 Preview 可以接收文本、图像和视频；但同一页面的规格表只明确列出文本和图像输入、文本输出。

这两处表述并不完全一致。

仓库中已经包含视觉编码器和图像验证脚本，因此图像输入较为明确。视频是否在当前开源权重、所有部署框架和托管 API 中以相同方式提供，不能只根据介绍段落下结论。

如果你的项目依赖视频理解，部署前应确认三件事：

- 当前使用的 vLLM、SGLang 或 API 版本是否开放视频输入；
- 视频是原生输入，还是先抽帧后按多张图片处理；
- 帧数、文件大小、上下文占用和计费方式分别是什么。

在这些问题没有通过实际接口确认前，不要把“支持视频”写进对客户的交付承诺。

## Step 5 Preview 强在哪里，哪些仍是发布方口径

StepFun 把模型定位为“面向智能体工作的旗舰模型”，重点列出四类能力：

- 仓库级软件工程、前端和设备编程；
- 需要多轮工具调用、执行、验证和修改的长周期任务；
- 结合长文档、图表、截图和图像的专业知识工作；
- 定量推理、财务资料和研究报告结合的金融任务。

模型卡还公布了软件工程、Agent 和专业知识等评测结果，其中部分结果使用 High reasoning 设置，部分数据来自指定 harness 或第三方榜单。

这些成绩能说明模型值得测试，但不能直接证明它在你的仓库和财务材料上“领先”。Agent 评测尤其受工具权限、最大运行时间、调用次数、提示词和重试策略影响。

真正有用的评估，不是再问一道公开编程题，而是拿一项你过去真实做过、已经知道正确结果的任务进行盲测。

## 不部署模型，也能完成的三项实测

如果只通过官方或第三方 API 体验，可以准备下面三个任务。它们比随口聊天更容易看出模型的真实能力。

### 测试一：修复一个有测试用例的代码问题

准备一个中等规模仓库和一条真实 issue，允许模型搜索文件、修改代码并运行测试。不要告诉它具体答案，只提供复现步骤和验收条件。

最后检查：

```text
[ ] 是否先复现问题，而不是直接猜原因
[ ] 是否只修改必要文件
[ ] 是否补充或更新测试
[ ] 是否运行完整相关测试集
[ ] 是否解释潜在回归风险
```

一个真正适合软件工程 Agent 的模型，不只是能生成看起来合理的补丁，而是能完成“定位—修改—验证—复盘”的闭环。

### 测试二：在长材料里寻找互相矛盾的信息

准备合同、会议纪要、需求文档和邮件，把其中三处关键数字故意设置成不一致。要求模型列出冲突位置、引用原文并说明需要谁确认。

这个任务能同时测试长上下文检索、来源定位和是否会擅自替你做决定。

### 测试三：做一份可复核的财务分析

给模型三年财报和一份行业报告，要求计算收入增速、毛利率、现金流变化，并把每个数字对应到页码或表格。

重点不是文字是否像分析师，而是：

- 计算能否复算；
- 单位和币种是否统一；
- 是否区分公司披露与模型推断；
- 遇到缺失数据是否明确说明；
- 是否引用了错误年份或合并口径。

金融是 StepFun 特别强调的方向，也正因为如此，更应该用可复核数字测试，而不是让模型自由发挥一篇市场展望。

## 真要私有化部署，官方示例需要什么硬件

Step 5 Preview 提供 FP8、BF16 和 NVFP4 等权重版本。官方说明支持通过 vLLM 或 SGLang 暴露 OpenAI 兼容 API，也提供 Transformers 离线生成实现。

部署文档给出的起点大致如下：

| 权重 | 官方示例硬件   | 说明                         |
| ---- | -------------- | ---------------------------- |
| FP8  | 单机 4×B300    | 支持张量、专家或数据并行组合 |
| FP8  | 单机 8×H200    | 使用默认 MoE 后端            |
| BF16 | 单机 8×B300    | 权重与 FP8 必须分开下载      |
| BF16 | 两节点 16×H200 | 需要高速网络和多节点配置     |

这只是“可以开始加载和测试”的参考，不是生产环境容量规划。并发请求、完整百万上下文、工具调用和多模态输入都会继续增加资源需求。

另外，给 FP8 权重加一个 `bfloat16` 参数不会把量化权重变回 BF16。需要 BF16 精度时，必须下载对应 BF16 检查点。

对于没有这类硬件和运维团队的公司，更合理的顺序通常是：先通过 API 验证业务价值，再租用 GPU 做小规模私有化测试，最后才评估长期自建集群。不要因为权重开放，就默认自建一定比 API 便宜。

## “开放权重”不等于 Apache 2.0，商业使用先读许可证

Step 5 Preview 使用 **StepFun Model License 1.0**，并不是 Apache 2.0 或 MIT。

许可证允许全球范围内免费使用、复制、分发、再许可和修改模型，也提供相应专利许可。但它附带几个对商业项目很重要的条件：

1. 分发模型或衍生模型时，需要保留许可证、版权、专利、商标和归属信息，并说明修改内容；
2. 单月活跃用户超过 1 亿，或单月营收超过 2000 万美元的相关商业产品，需要显著展示“Powered by StepFun AI”等归属信息；
3. 面向消费者销售手机、汽车、眼镜、机器人或智能家居等硬件，并首次把模型能力作为商业功能提供时，需要另行取得商业许可；
4. 运营 MaaS 业务且关联主体连续 12 个月总收入超过 2000 万美元时，也需要另行签署商业许可。

普通个人研究、企业内部使用和一般应用开发通常不会立刻触发这些门槛，但准备做模型 API 服务、智能硬件或大规模商业分发的团队，不能只看 Hugging Face 页面上的“可下载”就开始上线。

这里不是法律意见。正式商用前，应由团队根据产品形态、收入规模、分发方式和认证渠道逐条核对许可证原文。

## 最后怎么判断它适不适合你

Step 5 Preview 的价值很明确：开放权重、超长上下文、Agent 和多模态能力，让企业多了一个可控部署的旗舰模型选择。

但它不是“每个人都能本地跑的 27B 模型”，也不是把上下文设置成 100 万就能自动解决复杂工作。对个人用户，最实际的入口是 API；对企业，真正需要验证的是任务完成率、显存与吞吐、数据合规、框架稳定性和许可证，而不是参数表有多壮观。

如果一个模型能让代码修复少返工、让长文档引用可追溯、让财务计算可以复核，它才真正适合智能体工作。否则，6000 亿参数也只是一张很贵的配置表。
