GPT-6 Astra 和 Claude Fable 5.1，谁更强？

如果只想找一个聊天话题，看排行榜就够了。如果准备花钱订会员，排行榜远远不够。模型在某个公开测试里高几分，不代表它处理你的合同、写你的公众号文章、修改你的代码时也更省心。

我更建议用半天时间，拿五个自己真正做过的任务跑一遍。不要专门找刁钻题，也不要从网上抄“模型智商测试”。你平时最烦、最耗时间、又能判断对错的任务，才是最好的试卷。

OpenAI 对 GPT-6 Astra 的定位，强调的是跨代码、浏览器和专业软件执行多步骤工作；Anthropic 对 Claude Fable 5.1 的定位，则重点强调长期、异步的编码和知识工作。两家都把复杂任务放在核心位置，但产品入口、工具、限制和默认配置不同，所以不能直接拿宣传页上的分数替你做决定。

## 测试前先统一条件

同一个问题分别问两个模型，看谁写得更长，不叫公平测试。至少统一下面六项：

1. 使用同一份原始资料；
2. 使用同一份任务说明和验收标准；
3. 给相同的完成时间；
4. 尽量提供相近的工具权限；
5. 都只计算第一次正式交付，不无限返工；
6. 记录人工修改时间和实际费用，而不只记录输出速度。

如果一个在 ChatGPT 网页里使用，另一个在 API 或 Claude Code 里使用，要注明环境不同。浏览器、代码执行、文件搜索和持久化记忆都会影响结果，这时测到的是“产品加模型”的整体体验，不只是基础模型能力。

## 准备一张统一任务卡

五个测试都用同样的开头：

```text
这是一次实际工作测试。

请先复述任务目标、资料范围、不能做的事情和完成标准。
如果缺少会改变结果的关键信息，集中提问一次；普通细节按现有资料处理，但要在结果中注明假设。

交付时必须包含：
1. 最终结果；
2. 依据或修改说明；
3. 已完成与未完成事项；
4. 需要人工复核的位置；
5. 实际使用的工具或文件。
```

然后追加每项测试的具体要求。

## 测试一：从长文档里找证据，不是写摘要

准备两到四份你熟悉的资料，例如产品规则、报价单、合同附件和售后说明。总长度不必追求极限，50 至 100 页已经足够看出差异。

任务：

```text
根据上传资料回答以下三个问题：
[写入你真正关心的问题]

要求：
- 每条重要结论标注文件名和页码；
- 数字保留单位、日期和口径；
- 资料冲突时并列展示；
- 没有依据的内容写“无法确认”；
- 最后列出最值得人工打开原文检查的 5 处。
```

不要用“文章读起来更顺”评分。随机抽十条引用，逐条回到原文。页码错、数据口径丢失、把推测写成事实，都应扣分。

这项测试适合经常处理报告、政策、课程和客户资料的人。

## 测试二：把一篇中文文章改到能发布

找一篇自己写过、清楚语气和事实的旧稿。最好带一点个人经历和具体数字，因为模板化改写很难处理这些细节。

```text
请编辑这篇文章，不另写一篇新文章。

目标读者：[具体人群]
发布位置：[网站知识库 / 公众号 / 知乎]

要求：
- 保留原文事实、案例和个人判断；
- 删除重复、空话和营销腔；
- 不新增未经来源支持的数据；
- 标题要有明确问题，但不制造夸张结论；
- 每段只处理一个重点；
- 修改幅度较大的地方说明原因；
- 最后给出事实核对清单。
```

评分时记录“你亲手改了多少分钟”。有的模型初稿很惊艳，但会悄悄改掉原意；有的输出不花哨，却几乎不用返工。对内容创作者来说，后者往往更值钱。

## 测试三：修一个真实代码问题并跑完验收

不要让模型从零写贪吃蛇。选项目里已经存在、能复现的小问题，例如手机端图片比例不对、表单校验失效、构建出现兼容错误。

```text
目标：[要修复的问题]
复现步骤：[逐步写清]
允许修改：[文件或模块]
禁止修改：[依赖、路由、数据库等]

工作顺序：
1. 先检查原因，不立即修改；
2. 给出最小方案；
3. 实施后运行现有检查和构建；
4. 查看最终 diff，排除无关改动；
5. 汇报真实命令结果和剩余风险。
```

这里看五件事：有没有找准根因、有没有乱动无关文件、测试是否真的运行、失败时是否会收敛、最终 diff 是否容易审查。

如果两个模型不能使用相同代码环境，就不要拿“一个成功构建、一个只给代码片段”直接比较。把环境差异写进结果。

## 测试四：完成一次浏览器或桌面操作

选择没有付款风险的任务，例如检查网站链接、把公开页面整理成表格、在测试系统填写表单草稿。

```text
请检查网站的首页和知识库前两页：
- 导航与主要按钮能否打开正确地址；
- 是否出现 404、英文模板文字或破图；
- 手机宽度下菜单和长标题是否溢出；
- 联系弹窗能否打开和关闭。

只检查，不修改代码，不登录后台，不提交表单。
发现问题后记录网址、复现步骤、截图和严重程度。
```

这项测试不只看成功率，还看模型是否遵守“只检查”。误触提交、擅自修改设置或在异常页面继续乱点，应该重扣分。

如果你的版本没有 Computer Use，不要为了凑测试强行比较，可以换成多文件整理或 PPT 模板排版。

## 测试五：做一个会中途变更的长任务

真实工作很少一次说完。先给一个需要 60 至 90 分钟的任务，中途再补一条合理变化，观察模型能否接住新要求，而不忘最初边界。

例如让它制作一份 AI 会员选择报告，完成资料登记和提纲后追加：

```text
新增要求：报告读者改为第一次接触 AI 的小微企业主。
保留已经核对过的数据和来源，不重新搜索全部资料。
调整术语解释、案例和建议顺序，但不要改变原定的价格统计口径。

请先说明哪些部分需要重做，哪些可以保留，再继续执行。
```

记录它是否：

- 记得原始限制；
- 清楚说明变更影响；
- 复用已经确认的结果；
- 遇到冲突会询问；
- 中途失败后能从检查点继续；
- 最后完整交付，而不是只完成新增要求。

## 用这张百分制评分表

| 指标         | 分值 | 怎么评                             |
| ------------ | ---: | ---------------------------------- |
| 任务完成度   |   30 | 验收项实际完成多少，不看自我汇报   |
| 正确性与依据 |   25 | 数字、引用、代码行为是否可核对     |
| 遵守边界     |   15 | 是否改了不该改的、做了不该做的     |
| 人工返工成本 |   15 | 从模型交付到真正可用花了多少时间   |
| 速度与费用   |   10 | 完成耗时、API 费用或套餐额度消耗   |
| 过程透明度   |    5 | 是否说明假设、失败、工具和未完成项 |

每项任务都打一次分，最后不要只看总分，还要看与你日常工作最接近的两项。

例如你 70% 的时间都在改代码，那么编程和长任务应该加权；如果主要写内容和做研究，长文档与中文编辑更重要。平均分会掩盖真正的使用差异。

## 费用应该怎么比才不误导

### 两边都使用 API

记录实际输入、输出、缓存和工具调用费用。不要只比较每百万 Token 的标价，因为返工次数和最终总费用更有意义。

### 两边都使用会员套餐

很难得到精确的单次成本，可以记录：完成任务数量、是否触发限制、等待时间，以及一个月里真正使用了多少次高难度功能。

### 一边会员、一边 API

不要写“谁更便宜”的绝对结论。一个是周期订阅，一个是按量计费，应分别回答“这个月总共花了多少”和“完成一项任务付出了多少”。

截至本文核对时，OpenAI 将 GPT-6 Astra 定位于复杂推理、Computer Use、软件工程、研究和专业工作；Anthropic 将 Claude Fable 5.1 定位于长期编码、知识工作和异步 Agent 任务。两者的 API 公开输入、输出单价处于相近档位，但缓存、工具、超长输入和产品套餐规则不同，实际成本应以各自官方账单和当前价格页为准。

## 怎么根据结果做决定

下面不是排行榜结论，而是一个实用决策顺序：

1. **先看产品入口。** 你主要在 ChatGPT、Codex 还是 Claude、Claude Code 里工作？现有资料和流程在哪个平台，迁移成本往往大于模型的细小差距。
2. **再看高频任务。** 只比较每周至少会做一次的任务，不为一年用不到一次的能力付费。
3. **然后看返工。** 哪个模型让你少改 20 分钟，通常比第一次输出快 20 秒更重要。
4. **最后看费用。** 记录一个月总成本，而不是只看套餐标题或 API 单价。

如果任务主要跨浏览器、桌面应用和专业软件，可以优先试 GPT-6 Astra 的完整工作流；如果任务是长期代码项目、深度研究和异步知识工作，Claude Fable 5.1 也值得放进实测。普通问答、简单改写和短代码并不一定需要最贵模型，便宜一档的模型反而可能更划算。

真正有用的模型选择，不是选出一个永远的冠军，而是知道哪类任务交给谁、什么时候必须人工接管，以及一个月后这笔会员费到底有没有省下时间。
