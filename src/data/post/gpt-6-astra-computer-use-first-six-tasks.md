第一次看到 Computer Use 演示，最容易冒出的念头是：以后订票、下单、回邮件，全让 AI 做不就行了？

我的建议恰好相反。第一次不要碰付款，不要让它批量发消息，也不要让它整理唯一一份重要文件。先挑那些“做错了容易发现、发现后容易恢复”的任务，把控制边界跑顺。

Computer Use 不是模型突然住进了你的电脑。它仍然需要一个可以操作的环境、系统权限和应用访问范围，通过截图或界面状态判断下一步。你使用的 ChatGPT、Codex 或企业工作区没有出现相关入口时，不能仅凭订阅名称判断一定可用，具体以当前客户端、模型选择器和管理员设置为准。

如果入口已经出现，下面六个任务很适合练手。

## 先定三条权限，不要直接说“你看着办”

开始前，先把所有动作分成三级：

| 级别            | 可以做什么                       | 常见例子                                             |
| --------------- | -------------------------------- | ---------------------------------------------------- |
| A：直接执行     | 只读、可撤销、不会对外产生结果   | 打开网页、读取公开信息、切换页面、生成本地草稿       |
| B：执行前确认   | 会修改本地文件或应用状态         | 重命名文件、调整设置、填写表单、修改日历草稿         |
| C：禁止自动执行 | 会产生付款、发布、删除或账号风险 | 提交订单、发送邮件、删除原文件、修改密码、授权第三方 |

可以把这段放在每个 Computer Use 任务最前面：

```text
本次任务采用以下权限规则：

A 类动作可以直接执行：浏览公开页面、读取内容、截图、整理草稿。
B 类动作必须先展示变更清单，经我确认后才能执行：填写表单、修改文件、改变应用设置。
C 类动作不得执行：付款、提交订单、发送消息、发布内容、删除文件、登录新账号、修改密码、授权第三方。

遇到登录、验证码、隐私授权、费用确认或不确定页面时，立即暂停并告诉我当前界面，不要尝试绕过。
```

权限写清楚后，再开始下面的练习。

## 任务一：把多个网页整理成可核对的比较表

这是最稳妥的起点。模型只需要打开页面、读取公开信息并整理结果，不需要登录，也不会修改外部数据。

例如比较四款 AI 会员套餐：

```text
请查看我提供的 4 个官方产品页面，整理一张比较表。

只记录页面明确写出的信息，包括：套餐名称、计费周期、主要功能、使用限制、取消方式和信息更新时间。
每一行保留来源链接；页面没写的内容标记“未说明”，不要根据常识补全。

先展示准备访问的页面列表，我确认后再开始。
最终只生成草稿，不登录、不购买、不点击订阅按钮。
```

验收时随机打开两条来源，检查价格、日期和限制是否与原页面一致。重点不是表格看起来多完整，而是每项信息能不能回到出处。

## 任务二：填写表单草稿，但停在提交前

报销、报名、客户资料登记这些任务很机械，也很适合 Computer Use。但第一阶段只让它填，不让它交。

准备一份已经脱敏的数据，再写清楚字段对应关系：

```text
请根据“报名信息.txt”填写当前页面。

规则：
- 只填写文件中明确提供的字段；
- 缺失项保持空白，并列在待确认清单；
- 不上传身份证、银行卡或其他未授权文件；
- 填完后逐项截图或列出字段和值；
- 必须停在“提交”按钮之前，等待我检查。
```

这类任务最容易暴露界面操作的问题：下拉框选错、日期格式不兼容、页面自动清空。练习价值比让它下单高得多。

## 任务三：检查你自己的网站，而不是直接改网站

让 Computer Use 做网页巡检，是风险低、收益很高的场景。它可以像真实访客一样点导航、打开文章、测试手机菜单，发现只有浏览器里才会出现的问题。

```text
请以普通访客身份检查这个网站，不修改代码。

依次检查：
1. 顶部导航能否到达正确页面；
2. 首页主要按钮是否有效；
3. 联系客服弹窗能否打开和关闭；
4. 知识库前两页的文章链接是否正常；
5. 手机宽度下菜单、图片和长标题是否溢出；
6. 是否出现英文模板文字、空白图片或 404。

发现问题时记录：页面地址、复现步骤、截图和严重程度。
不要登录后台，不要改文件，只交付问题清单。
```

如果你同时使用代码 Agent，先让 Computer Use 找问题，再把确认的问题交给代码 Agent 修。不要把“检查”和“修改”混成一步。

## 任务四：把资料排进已有文档或 PPT 模板

这里的重点是“已有模板”。如果只说“做一份高级 PPT”，模型会把大量时间花在猜你的审美。给它一份真实模板，再明确哪些内容不能改，结果稳定得多。

```text
请把“9月运营复盘.md”中的内容整理进当前演示文稿。

要求：
- 保留母版、字体、页脚和品牌色；
- 不新增外部图片；
- 每页只表达一个结论；
- 数字必须与原文一致；
- 超出页面的内容放入备注，不缩到难以阅读；
- 完成后输出逐页修改清单。

只保存为新副本，不能覆盖原模板。
```

检查时不要只翻第一页。重点看表格是否被截断、字号是否突然变小、图表坐标是否改变，以及演讲备注是否还在。

## 任务五：整理下载目录，但只先给重命名方案

文件整理看似简单，实际上很适合测试模型是否会尊重边界。第一轮只让它扫描指定目录并生成映射表，不执行移动和删除。

```text
只检查“Downloads/待整理”目录，不访问其他目录。

请输出重命名建议表：
原文件名｜建议文件名｜文件类型｜判断依据｜目标文件夹

命名格式：日期-主题-版本号.扩展名
重复文件只标记，不删除；无法判断内容的文件保持原名。
先给方案，等我确认后才能批量重命名或移动。
```

确认时特别检查扩展名、同名文件和日期。永远不要把云盘同步目录作为第一次练手的位置。

## 任务六：起草日历和邮件，但不对外发送

跨应用工作流是 Computer Use 的优势之一，但也最容易产生真实影响。安全做法是让它先完成“草稿层”。

```text
根据会议纪要起草后续安排：

1. 列出决定事项、负责人和截止时间；
2. 生成日历事件草稿，包括标题、时间、参与人和备注；
3. 生成一封确认邮件草稿；
4. 把会议纪要中没有明确写出的时间或负责人列为待确认项。

不得发送邮件，不得邀请参与人，不得写入正式日历。
完成后集中展示全部草稿，等待我确认。
```

这能省掉整理时间，又不会因为一个错误日期直接通知十几个人。

## 给任务设置“停止条件”，比要求它聪明更有效

Computer Use 最危险的情况，不一定是明显报错，而是页面和预期不一样时还继续尝试。每个任务最好补上停止条件：

- 页面要求登录或重新验证身份；
- 出现验证码、风险提示或服务条款确认；
- 按钮文字与任务描述不一致；
- 页面出现付款金额；
- 要访问任务范围之外的文件夹或应用；
- 连续两次操作没有得到预期结果；
- 需要猜测联系人、地址、时间或账号。

可以直接写：

```text
触发任意停止条件后，不要继续试错。保留当前页面，说明已经完成什么、卡在哪里、需要我决定什么。
```

## 结束时一定要索要操作记录

不要只接受一句“已经完成”。让模型按以下格式交付：

```text
请输出任务记录：
1. 实际访问的页面和应用；
2. 已执行的动作；
3. 没有执行的动作；
4. 创建或修改的文件；
5. 需要人工核对的项目；
6. 是否触发过停止条件；
7. 最终结果保存在哪里。
```

然后自己抽查关键结果。网页比较任务抽查来源，表单任务逐项对字段，文件任务核对数量，PPT 任务检查每一页。Computer Use 的价值不是让人退出流程，而是把人从每一次点击里解放出来，集中精力检查结果。

## 第一次使用的完整检查清单

- 使用单独的测试目录或文件副本；
- 只开放任务需要的应用和页面；
- 先做只读任务；
- 把付款、发送、发布、删除列为禁止动作；
- 登录和验证码交给本人处理；
- 不使用 Computer Use 绕过网站限制或安全验证；
- 给出明确停止条件；
- 任务结束后检查操作记录；
- 重要结果保留人工确认；
- 连续三次稳定完成后，再考虑扩大权限。

OpenAI 的 Computer Use 文档也把浏览器任务、图形界面测试、跨应用工作流等列为适合场景，并明确这些能力仍受系统权限和应用访问控制。真正好用的起点不是“完全托管电脑”，而是把边界内的重复操作交出去，把不可逆动作留在人手里。
