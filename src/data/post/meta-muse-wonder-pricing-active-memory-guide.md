当一家公司发布新模型时，最省事的写法是把跑分抄一遍，再得出“又一个 GPT、Claude 挑战者”的结论。

Meta 2026 年 10 月 12 日发布的 **Muse Wonder** 和 **Muse Wonder Full**，真正值得看的却不是榜单，而是它们试图解决两个更日常的问题：AI 为什么总是忘记用户长期在做什么，以及任务一复杂，Agent 为什么容易半路跑偏。

Meta 给出的答案叫 **Active Memory** 和 **Active Focus**。

Active Memory 让模型跨对话保留与用户有关的重要信息，并在合适的任务中取回；Active Focus 则让 Agent 在遇到困难时继续围绕目标工作，尝试其他方法、从错误中恢复，在重要操作前请求确认。

这比“回答更聪明”更接近真正的私人助理。但它也意味着模型需要接触更多文件、日历、消息和长期偏好。能力越贴身，隐私和权限越不能靠默认设置。

> 本文依据 Meta 官方发布说明及 TechCrunch、Axios 的报道整理。Meta 对模型表现的描述主要来自自家评测，独立测试仍在进行；Muse Wonder Full 也不是所有 Muse 用户已经可以直接使用。功能、价格和开放范围以账户页面为准。

## 两个模型、三个入口，先别把它们混在一起

Meta 这次发布的不是一个模型，也不是只有一种购买方式。

### Muse Wonder

标准版已经通过 **Meta Model API** 和 **Muse Code** 提供给开发者，未来还会进入 Muse 应用，并优先向订阅用户推出。

它适合开发者通过 API 集成，也适合在代码工作流中体验。媒体援引公开定价信息称，API 价格为每百万输入 token 4 美元、输出 token 20 美元。API 按量计费，不等于每月 20 美元无限使用。

### Muse Wonder Full

Full 是能力更完整的版本，目前主要面向 Muse Code 订阅用户。公开信息显示，对应的 Muse Code 档位为每月 50 或 200 美元。

Meta 计划未来让 Full 驱动 Muse AI 智能体，但没有给出确切时间。现在购买普通 Muse 订阅，不能自动推导出“已经能使用 Wonder Full”。

### Muse 应用订阅

Muse 应用目前有每月 20 或 100 美元的订阅档。Meta 表示 Muse Wonder 会先向订阅用户逐步推出，但“即日起 API 可用”和“即日起所有 Muse 订阅用户都可用”是两件不同的事。

如果你只是普通用户，购买前先在应用的模型选择器和套餐说明里确认是否已经出现 Muse Wonder；如果你是开发者，则要区分月度订阅和按 token 计费的 API。

## Active Memory 到底能解决什么

普通聊天工具最大的问题，是每次开新对话都要重新交代背景。

你正在准备一份持续两个月的产品方案，AI 需要知道目标用户、预算、品牌语气、已经否决的方向和最新决策。传统做法是每次复制一大段项目说明，或者维护一个“背景提示词”文档。

Active Memory 想把这件事自动化。理想情况下，你只需要在第一次说明：

```text
这个项目面向 35—50 岁的小企业主，预算不超过 8 万元；
不要使用夸张承诺，所有案例必须注明来源；
以后讨论这个项目时，优先沿用这三条规则。
```

几天后让它写落地页、检查广告或整理客户反馈，模型能够主动取回这些约束，而不是重新猜一遍。

真正有价值的不是“记住你喜欢喝咖啡”，而是记住会影响任务质量的稳定信息：

- 项目目标与受众；
- 已确认的品牌和格式规范；
- 长期工作偏好；
- 已作出的决策及其原因；
- 不能触碰的预算、合规和隐私边界。

如果记忆做得好，用户减少重复说明，Agent 也更不容易前后矛盾。

## Active Focus 不是让模型永远不出错

复杂 Agent 经常出现一种“很勤奋地跑偏”：它做了很多步骤、生成很多文件，最后交付的东西却偏离原始目标。

Active Focus 的设计目标，是让模型在任务受阻时仍保持目标感。按照 Meta 的描述，它能够尝试替代方案、从错误中恢复、需要信息时主动提问，并在重要操作前与用户确认。

例如让 Agent 完成下面的任务：

```text
读取近三个月客户反馈，找出退订的主要原因，
给出按影响排序的修复计划，但不要修改生产系统。
```

一个合格的 Agent 不应该因为找不到某份表格，就随便用旧数据补齐；也不应该在没有授权时直接修改线上配置。它应该停下来说明缺少什么，或者换一种数据来源，并在执行不可逆操作前再次确认。

不过，“会自我纠错”依然是厂商对能力的描述，不是零失误承诺。涉及付款、发邮件、删除文件、修改生产环境时，人仍然应该保留最后确认权。

## Meta 说“对标领先模型”，应该怎么读

Meta 称 Muse Wonder 系列在个人与专业 Agent 任务、法律、金融、健康和编程等领域达到前沿水平，并与 OpenAI、Anthropic 的领先模型竞争。

这类表述在发布日很常见，但至少要加三个限定：

1. 发布方通常使用自己选择的测试集、提示词和工具环境；
2. Agent 成绩非常依赖工具权限、运行时长和尝试次数；
3. 跑分相近，不代表在你的中文资料、公司系统和真实流程中同样可靠。

所以不要根据一张榜单直接年付。最有价值的测试，是拿自己的三个任务比较：同样材料、同样目标、同样时间和费用，看谁完成得更稳定。

## 一套三天就能完成的实测方法

如果你的账户已经获得 Muse Wonder，可以用三天做一次小型验收，而不是随便问几个知识题。

### 第一天：测试长任务是否跑偏

准备一个 30—50 页的真实材料包，让模型完成：

1. 提取关键事实并标注出处；
2. 找出冲突和缺失信息；
3. 生成一份有明确受众的交付物；
4. 按检查清单自检并修改一次。

记录它是否漏掉限制条件，是否凭空补充信息，遇到不确定内容会不会主动提问。

### 第二天：测试记忆是否真的有用

在新对话中继续同一项目，但不要重新粘贴全部背景。检查它能否正确取回昨天确认的目标、语气和限制。

再故意修改一条规则，例如把预算从 8 万元改为 5 万元。看看系统是保留新规则、仍沿用旧值，还是出现互相矛盾的记忆。

### 第三天：测试权限边界

如果连接了邮件、日历或云盘，先只授权一个测试文件夹和测试账号。让 Agent 草拟邮件，但不要允许自动发送；让它建议日程，但不要直接邀请真实客户。

观察它在以下动作前是否请求确认：

- 向外部人员发送内容；
- 覆盖或删除文件；
- 使用个人敏感信息；
- 执行付费操作；
- 将一个项目的信息带入另一个项目。

三天结束后，用“正确率、返工时间、总费用、权限风险”四项打分。真正值得付费的 Agent，应该减少你的检查成本，而不是只生成更多需要检查的内容。

## 长期记忆越强，越要先做隐私分区

Meta 在发布说明中强调，模型经过训练以避免未经许可分享私人信息，并会在重要操作前确认。这是必要的安全设计，但用户仍应主动做权限分区。

建议把信息分成三类：

### 可以长期记住

- 写作风格、输出格式；
- 公开的项目背景；
- 不涉及个人身份的工作偏好。

### 只在单次任务使用

- 未发布的商业计划；
- 客户材料与内部会议记录；
- 带有合同、财务和员工信息的文档。

### 不应交给通用 Agent

- 密码、私钥、验证码；
- 完整身份证件与银行卡信息；
- 没有授权处理的客户隐私；
- 能直接操作生产系统的最高权限凭据。

另外，定期检查记忆管理页面：模型记住了什么、能否删除、删除后是否影响关联数据。企业使用时，还要确认数据是否用于训练、保存多久、管理员是否能导出审计记录，以及离职员工的权限如何收回。

## 20 美元订阅值不值，关键不是“模型强不强”

如果你每月只问几十个零散问题，长期记忆和 Agent 能力可能不会带来明显价值，免费工具或已有订阅更合适。

如果你长期处理同一个项目，经常需要重复交代背景，或者已经把 AI 接入日历、邮件、文件和代码仓库，Muse Wonder 的方向值得认真测试。它的价值不在于多答对一道题，而在于能否减少重复说明、降低任务跑偏和返工。

但不要为了“记忆”本身付费。真正的标准是：它记住的内容是否准确、过期信息能否更新、敏感信息能否删除、执行前是否确认，以及出现错误时你能否追溯它用了哪些资料。

AI 助理越像一个长期同事，管理它的方法也越应该像管理一个同事：给清楚的目标、最小必要权限、可检查的交付标准，以及随时能够收回的访问权。
